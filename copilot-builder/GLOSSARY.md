# GLOSSARY — słowa tego repozytorium i ich nazwy w kodzie

Proza jest po polsku, identyfikatory po angielsku, więc szukanie słowa wprost często nic nie daje. Tabela
mapuje w obie strony: termin → gdzie w kodzie; nazwa z kodu → co znaczy. Kolumnę „gdzie w kodzie" sprawdza
`npm run check:glossary` — każdy odnośnik `` `ścieżka` `` albo `` `ścieżka#Symbol` `` musi istnieć. Kolumna
„nie mów" to synonimy, których nie używamy, żeby jedna rzecz miała jedną nazwę.

| termin                        | znaczenie                                                                                                    | gdzie w kodzie                                                                                    | nie mów                          |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- | -------------------------------- |
| brama (gate)                  | jeden krok `npm run verify`; czerwona przerywa, zielona nic nie mówi                                          | `tools/scripts/verify.mjs#STATIC`, `tools/scripts/verify.mjs#CODE`                                | check, test (gdy chodzi o bramę) |
| definicja ukończenia (DoD)    | wszystkie AC ✅, analyze GO, review APPROVED, `npm run verify` zielone, run-log domknięty                        | `.github/prompts/dod.prompt.md`, `docs/sdd/methodology.md`                                        | „gotowe", „działa u mnie"        |
| affected                      | projekty dotknięte zmianą: pliki pod `root` projektu + zależni transytywnie; zmiana pliku korzenia = wszystkie | `tools/scripts/affected.mjs#affectedProjects`, `tools/scripts/affected.mjs#ROOT_TRIGGERS`         | changed projects, nx affected    |
| graf projektów                | krawędź = import aliasu `@cb/*` z `tsconfig.json`; `<app>-e2e` zależy od `<app>`                              | `tools/scripts/affected.mjs#buildGraph`, `tools/scripts/affected.mjs#readWorkspace`               | project graph Nx                 |
| cache zadań                   | marker w `.cache/tasks/` po zielonym `lint`/`typecheck`/`test`; klucz = hash treści projektu i zależności      | `tools/scripts/affected.mjs#taskHash`                                                             | remote cache, Nx cache           |
| alias biblioteki              | `@cb/<zakres>/<typ>-<nazwa>` → `libs/<zakres>/<typ>-<nazwa>/src/public-api.ts`; jedyna droga importu          | `tools/scripts/new-project.mjs#newLibrary`, `eslint.rules.mjs#DEEP_IMPORTS`                        | ścieżka względna między libs     |
| typ biblioteki                | `feature`, `ui`, `data-access`, `util` — pierwszy segment nazwy; wyznacza kierunek zależności                  | `tools/scripts/new-project.mjs#LIB_TYPES`, `eslint.rules.mjs#UTIL_ONLY`                            | warstwa, kategoria               |
| granice modułów               | `no-restricted-imports` na wzorcach aliasów, pełna lista wzorców per warstwa                                  | `eslint.rules.mjs#boundary`                                                                       | module boundaries Nx             |
| pin                           | wiersz deklarujący wersję zależności z uzasadnieniem `why`; jedyne miejsce, gdzie wersja jest decydowana       | `tools/scripts/pins.config.mjs#PINS`, `tools/scripts/check-pins.mjs#checkPins`                    | „wersja w package.json"          |
| zaległość pinu (upstream)     | ile dni pin jest za `latest`; zegar w `upstream-state.json`, `--ack` = świadoma decyzja „zostaję"             | `tools/scripts/check-upstream.mjs#checkUpstream`, `tools/scripts/upstream-state.json`             | outdated, przestarzałe           |
| stempel (stamp)               | `YYYY-MM-DD_HH-MM` w strefie warsztatu; w nazwach artefaktów i katalogów snapshotów                            | `tools/scripts/stamp.mjs#nowStamp`, `tools/scripts/stamp.mjs#STAMP_TIMEZONE`                       | timestamp, data                  |
| verb (SDD)                    | rodzaj zmiany: feature, fix, refactor, deps, chore, security, docs — w nazwie planu i run-logu                 | `tools/scripts/workflow-specify.mjs#VERBS`                                                        | typ zadania, operacja            |
| spec / plan / run-log         | trzy lokalne artefakty SDD jednego zadania (gitignorowane); scaffold ze szablonów                              | `docs/sdd/templates/spec.md`, `docs/sdd/templates/plan.md`, `docs/sdd/templates/run.md`           | ticket, task list, dziennik      |
| `[?]`                         | znacznik niepewności w spec/planie; `/clarify` domyka; spec `clarified` nie ma prawa go nieść                    | `tools/scripts/validate-sdd.mjs#validateSdd`                                                      | TODO, TBD                        |
| STOP-AND-ASK                  | zatrzymanie z jedną listą pytań (opcje, rekomendacja, wpływ) zamiast domysłu                                  | `.github/agents/orchestrator.agent.md`, `docs/sdd/methodology.md`                             | „założyłem, że…"                 |
| roster                        | lista agentów z rolą, tierem i widocznością; jedyne źródło prawdy                                              | `.github/models-registry.json`, `tools/scripts/validate-ai-config.mjs#validateAiConfig`           | lista agentów w AGENTS.md (to kopia) |
| tier                          | `junior`/`mid`/`vision` i trzy miejsca review `senior-anthropic`/`senior-openai`/`senior-moonshot` — klasa kosztowa modelu; nazwa modelu tylko w rejestrze | `.github/models-registry.json`                                                                    | nazwa modelu                     |
| rola agenta                   | orchestrator, writer, tester, verifier, reviewer, triager, integration — niesie uprawnienia (`tools:`)         | `.github/models-registry.json`, `tools/scripts/validate-ai-config.mjs#parseList`                  | „typ agenta"                     |
| miejsce review (seat)         | jedno z trzech zleceń review kodu o identycznym briefie i pełnym zakresie, na innej rodzinie modeli; liczba zgodnych rodzin = potwierdzenie | `.github/models-registry.json`, `tools/scripts/validate-ai-config.mjs#checkReviewSeats`           | drugi reviewer, second opinion   |
| commit zadania                | ukończone zadanie planu (`done_when` zielone) = jeden `git commit` wykonany przez `scm-git`, SHA w kolumnie `commit` planu; push — człowiek | `.github/agents/scm-git.agent.md`, `commitlint.config.mjs`                                         | propozycja commita, commit ręczny |
| brama STOP                    | werdykt STOP (`doc-reviewer`, STOP-AND-ASK): lista pytań kończy turę, orkiestrator czeka na odpowiedź operatora | `.github/agents/doc-reviewer.agent.md`, `.github/agents/orchestrator.agent.md`                    | „założyłem, że…", pytanie w przelocie |
| diagram (Mermaid)             | blok ```mermaid w `.md`: typ do treści, etykiety po polsku, bez kolorów; renderuje GitLab i podgląd VS Code | `.github/skills/mermaid-diagrams/SKILL.md`                                                         | obrazek, PNG w docs              |
| routing po ścieżce            | ścieżka dotykanego pliku wyznacza wykonawcę (`npm run route`); tabela orkiestratora generowana z konfiguracji; trzy obszary = trzy zlecenia | `tools/scripts/routing.config.mjs#BY_PATH`, `tools/scripts/route.mjs#routePath`                  | przydział, delegacja „na czucie" |
| brief zlecenia                | jedyny kształt delegacji: ZADANIE, PLIKI, AC, BRAMA, BUDŻET, ZWRÓĆ, NIE — bez historii rozmowy i cudzych raportów | `.github/agents/orchestrator.agent.md`                                                            | zlecenie „na czucie", przeklejony transkrypt |
| scalanie review               | trzy raporty miejsc review → jedna tabela z liczbą zgodnych rodzin, konfliktami 🔴/🟢 i werdyktem najgorszym z trzech (`npm run review:merge`) | `tools/scripts/review-merge.mjs#mergeReviews`, `.github/prompts/review.prompt.md`               | scalanie „w głowie", średnia z kolorów |
| blok instrukcji               | blockquote ≤ 600 B w `AGENTS.md` ≡ `.github/copilot-instructions.md` — cały koszt stały narzędzia w sesji      | `tools/scripts/check-instruction-sync.mjs#BLOCKS`, `tools/scripts/check-instruction-sync.mjs#BYTE_LIMIT` | prompt narzędzia            |
| snapshot (ALM)                | zrzut źródła ALM do `.scribe/<źródło>/<stempel>/<snapshot>/` z `_manifest.json`; czytany wybiórczo             | `tools/scribe/scripts/read.mjs#discoverPipelines`, `tools/scribe/integrations/shared/read-runtime.ts` | export, dump                 |
| źródło (ALM)                  | system upstream: jira, confluence, gitlab, sonar, figma, miro, browser-inspector; `xray` to osobne źródło, ale nie osobny system — Xray jest pluginem Jiry (te same poświadczenia, ten sam host)                          | `tools/scribe/scripts/read.mjs#selectSource`, `tools/scribe/examples/`                             | integracja (to katalog kodu)     |
| dry-run                       | domyślny tryb `alm:create`/`alm:update`: pokazuje (diff), nic nie zapisuje; `--yes` zapisuje                     | `tools/scribe/scripts/write.mjs#plan`, `tools/scribe/integrations/shared/write-runtime.ts`        | preview, symulacja               |
| proweniencja                  | linia „za pomocą narzędzia scribe v…" doklejana do każdego zapisu ALM                                          | `tools/scribe/integrations/shared/write-runtime.ts`, `tools/scribe/integrations/shared/version.ts` | podpis, stopka                   |
| flow                          | config JSON browser-inspectora: lista snapshotów `page`/`flow` z krokami                                        | `tools/browser-inspector/src/flow.mjs`, `tools/browser-inspector/templates/flow.md`               | scenariusz e2e (to Playwright)   |
| ref `eN`                      | identyfikator elementu w snapshocie sesji browser-inspectora; martwy po przerysowaniu → nowy `snap`             | `tools/browser-inspector/src/snapshot.mjs`, `tools/browser-inspector/src/session.mjs`             | selektor                         |
| keeper                        | lokalny proces trzymający ciepłą przeglądarkę między komendami sesji; gaśnie po bezczynności                    | `tools/browser-inspector/src/keeper.mjs`, `tools/browser-inspector/src/paths.mjs#CI_VARS`         | daemon, serwer                   |
| krok (step)                   | jedna akcja flow/sesji (`click`, `fill`, `waitFor`, `extract`…); nieudany krok = wynik w raporcie, nie wyjątek | `tools/browser-inspector/src/steps.schema.mjs`, `tools/browser-inspector/src/steps.run.mjs`       | komenda (to CLI)                 |

| artefakt MCP                  | surowa odpowiedź serwera MCP zapisana przez `mcp-gateway` do `.mcp-artifacts/`; wraca ścieżka + streszczenie     | `.github/agents/mcp-gateway.agent.md`, `.vscode/mcp.json`                                         | wynik narzędzia w czacie         |
| kanon wersji                  | blok AUTOGEN w `docs/tech-stack.md` regenerowany z `package.json`                                               | `tools/scripts/stack.mjs#renderBlock`, `docs/tech-stack.md`                                       | lista wersji w README            |

| runner testów Angulara        | `@angular/build:unit-test` (Vitest) z konfiguracją współdzieloną: progi pokrycia, reportery CI                  | `tools/testing/vitest-angular.config.mts`, `angular.json`                                          | karma, jest                      |

| biblioteka hooków             | wspólne pomocniki hooków: payload ze stdin, nazwa i wejście narzędzia, odpowiedź deny/allow                     | `tools/hooks/lib/payload.mjs#parsePayload`, `tools/hooks/lib/payload.mjs#denyDecision`            | biblioteka skryptów              |
| reguła TAG                    | plik niosący wersję pinu w innym kształcie (tag obrazu CI) musi nieść dokładnie wersję z pinu                  | `tools/scripts/check-pins.mjs#tagProblems`, `tools/scripts/pins.config.mjs`                       | LAG (proza cytująca wersję)      |
| skan sekretów                 | pre-commit: żadna wartość wyglądająca jak token, klucz prywatny czy hasło nie wchodzi do historii             | `tools/scripts/check-secrets.mjs#findSecrets`, `.githooks/pre-commit`                             | audit zależności (`npm audit`)   |
| indeks ze stage'a             | `CODE-INDEX.md` w pre-commit generowany z drzewa STAGE'OWANEGO (`--staged`), więc opisuje kod z commita       | `tools/scripts/index-code.mjs#exportStagedTree`, `.githooks/pre-commit`                           | indeks z working tree            |
| allowlista narzędzi           | hook read-only przepuszcza tylko nazwy narzędzi, które czytają; nieznane narzędzie = odmowa z nazwą listy      | `tools/hooks/deny-writes.mjs#READ_TOOLS`, `tools/hooks/format-on-edit.mjs#EDIT_TOOLS`             | lista `tools:` agenta (prośba)   |
