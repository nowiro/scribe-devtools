Trzy rzeczy, które zmieniają obraz

a) --minimal jest domyślnie true — od 0.21.0, PR #3027. npx -y nx-mcp@latest <ws> eksponuje dokładnie jedno narzędzie, nx_docs, za 358 tokenów (initialize 209 + tools/list 149) Z. Zero narzędzi o projektach, targetach i generatorach.

Dokumentacja Nx tłumaczy to wprost: te narzędzia „są teraz obsługiwane efektywniej przez agent skills, które dostarczają wiedzę domenową jako przyrostowo ładowane instrukcje zamiast zrzutów danych z wywołań narzędzi", i linkuje wpis „why we deleted most of our MCP tools" D. To ta sama teza, co całe to repozytorium — postawiona przez samych autorów Nx.

Zastrzeżenie z weryfikacji — i dlaczego tu nie obowiązuje

Ogólnie 358 to podłoga, nie własność samej flagi: --minimal nie ukrywa trzech narzędzi Nx Cloud ani trzech IDE, więc workspace z nxCloudId dostaje pod tymi samymi domyślnymi flagami 4 narzędzia i ~1 620 tokenów. W tym zespole Nx Cloud jest zabroniony, a Nx Console nie działa w sesji terminalowej — więc 358 jest tu wartością twardą, nie podłogą, i nx_docs jest jedynym narzędziem, jakie ten serwer kiedykolwiek pokaże.

b) Narzędzia workspace są zepsute na nx 23. Bundle ma zaszyte join(nxRoot, "src/utils/find-matching-projects"), a nx 23 przeniósł wszystko do dist/src/:

# D:/github/app-factory, nx 23.1.1

$ ls node_modules/nx/dist/src         istnieje
$ node -p "require('nx/package.json').bin"
{ nx: './dist/bin/nx.js', 'nx-cloud': './dist/bin/nx-cloud.js' }

# live stdio, nx_project_details:
Cannot find module 'D:/github/app-factory/node_modules/nx/src/utils/find-matching-projects'

Ten sam hardcode produkuje też Cannot find module '.../nx/src/native' na stderr, więc błąd układu dotyka więcej niż jednego miejsca wywołania. Osobno — i to była poprawka weryfikacji do pierwotnej diagnozy — nx_available_plugins pada z innego powodu: jego główne źródło zwraca HTTP 404, 14 bajtów (404: Not Found, bez znaku nowej linii, trzy przebiegi curl -L dziś), a wokół tego pobrania nie ma catch — w przeciwieństwie do pobrania listy community, które degraduje się do pustej listy. Jedna linijka catch zamieniłaby Internal error w częściowy wynik.

c) Telemetria domyślnie włączona. GA4 Measurement Protocol, POST do google-analytics.com/mp/collect, event action_triggered przy każdym wywołaniu narzędzia, z per-proces randomUUID jako client_id/user_id/session_id i user_properties {editor, os, appversion, nxversion} Ź. Gasi to --disableTelemetry, którego w konfiguracji użytkownika nie ma. Niezależnie od tego serwer dotenv-uje .local.env, .env.local i .env z roota workspace'u do własnego środowiska procesu Ź — warto wiedzieć, skoro proces potem wychodzi do sieci.

Ścieżka „co 30 sekund POST nazw branchy do Nx Cloud, po odczytaniu git config user.email i przefiltrowaniu 10 ostatnich lokalnych branchy po authoremail" Ź nie uruchamia się bez Nx Cloud — czyli tutaj nigdy. Notuję ją, bo jest w kodzie, nie dlatego, że dotyczy tego repozytorium.

Co użytkownik dostaje dziś — i dlaczego nx-mcp wychodzi w całości

Płaci 358 tokenów i 1 595 ms handshake'u za serwer, który w domyślnej konfiguracji odpowiada na jedno pytanie — a po odblokowaniu --no-minimal sześć z siedmiu narzędzi rzuca wyjątkiem na jego wersji nx. Jedynym narzędziem, którego zamiennik nie mógł odtworzyć uczciwie, były trzy narzędzia Nx Cloud; Nx Cloud jest w tym zespole zabroniony, więc ten wyjątek znika. nx-mcp nie ma już żadnego zastosowania, dla którego warto go trzymać.

I.5 Projekt zamiennika: nx-angular-inspector

Trzy niezależne projekty poszły przed panel sędziowski. Wygrał cienki wrapper bez keepera (46 pkt) przed „materializacją kontekstu do plików" (42) i „keeperem z ciepłym indeksem" (40). Poniżej wersja po wchłonięciu najlepszych pomysłów przegranych i po naprawieniu każdego zarzutu sędziów.

Zakres wsparcia: tylko nx >= 23 i angular >= 22

Decyzja właściciela, i jest tańsza, niż wygląda — kasuje całą klasę kodu zgodnościowego:
